## 1. Kết quả chạy PX4 SITL + Gazebo

Mục đích của phần này là kiểm tra xem **PX4 có thể chạy mô phỏng drone trên máy tính hay không**.

PX4 SITL có thể hiểu đơn giản là:

> Chạy PX4 trên máy tính thay vì chạy trên flight controller thật.

Gazebo là môi trường mô phỏng, nơi hiển thị drone X500 và mô phỏng chuyển động của drone.

Để chạy thử, sử dụng:

```bash
cd ~/PX4-Autopilot
make px4_sitl gz_x500
```

Sau khi chạy lệnh trên:

- Gazebo mở thành công.
- Mô hình drone `x500_0` xuất hiện trong Gazebo.
- PX4 khởi động thành công.
- Terminal PX4 xuất hiện dấu nhắc:

```text
pxh>
```

Một số log quan trọng:

```text
INFO  [gz_bridge] world: default, model: x500_0
INFO  [init] Setting camera to follow x500_0
INFO  [logger] logger started (mode=all)
INFO  [px4] Startup script returned successfully
pxh>
```

Ý nghĩa của các dòng trên:

- `model: x500_0`: PX4 đã kết nối với mô hình drone X500 trong Gazebo.
- `logger started`: PX4 đã bắt đầu ghi log chuyến bay.
- `Startup script returned successfully`: PX4 đã khởi động thành công.
- `pxh>`: có thể nhập lệnh trực tiếp vào PX4.

### Kết luận phần SITL

PX4 SITL và Gazebo đã chạy thành công.

```text
PX4 SITL       : PASS
Gazebo         : PASS
Drone X500     : PASS
PX4 Shell      : PASS
PX4 Logger     : PASS
```

Điều này chứng minh môi trường mô phỏng đã sẵn sàng để tiếp tục chạy thử chế độ Offboard.

## 2. Kết quả chạy Offboard qua ROS 2

Mục đích của phần này là kiểm tra xem **ROS 2 có thể gửi lệnh điều khiển đến PX4 hay không**.

Có thể hiểu luồng hoạt động như sau:

```text
ROS 2
  ↓
Micro XRCE-DDS Agent
  ↓
PX4
  ↓
Drone X500 trong Gazebo
```

Trong đó:

- **ROS 2**: chạy chương trình điều khiển Offboard.
- **Micro XRCE-DDS Agent**: làm cầu nối giữa ROS 2 và PX4.
- **PX4**: nhận lệnh và điều khiển drone.
- **Gazebo**: hiển thị drone bay trong môi trường mô phỏng.

Micro XRCE-DDS Agent được chạy bằng:

```bash
MicroXRCEAgent udp4 -p 8888
```

Sau khi PX4 kết nối với Agent, ROS 2 nhìn thấy các topic điều khiển quan trọng:

```text
/fmu/in/offboard_control_mode
/fmu/in/trajectory_setpoint
/fmu/in/vehicle_command
```

Điều này có nghĩa là:

> ROS 2 đã có thể gửi lệnh Offboard đến PX4.

Tiếp theo, chương trình Offboard được chạy bằng:

```bash
source /opt/ros/jazzy/setup.bash
source ~/ws_px4/install/px4_msgs/share/px4_msgs/local_setup.bash

~/ws_px4/build/px4_ros_com/offboard_control
```

Sau khi chạy, PX4 nhận được lệnh từ ROS 2 và báo:

```text
INFO  [commander] Armed by external command
INFO  [commander] Takeoff detected
```

Ý nghĩa:

- `Armed by external command`: PX4 đã nhận lệnh ARM từ chương trình Offboard.
- `Takeoff detected`: drone đã cất cánh thành công.

Kiểm tra trạng thái khi đang bay:

```text
INFO  [commander] Armed
INFO  [commander] navigation mode: Offboard
INFO  [commander] in failsafe: no
```

Ý nghĩa:

- `Armed`: drone đang ở trạng thái được phép hoạt động động cơ.
- `navigation mode: Offboard`: drone đang được điều khiển từ chương trình bên ngoài.
- `in failsafe: no`: PX4 không phát hiện lỗi nghiêm trọng trong quá trình bay.

Kiểm tra tín hiệu Offboard:

```text
offboard_control_signal_lost: False
```

Dòng này rất quan trọng vì nó cho biết:

> PX4 vẫn đang nhận liên tục tín hiệu điều khiển từ chương trình Offboard.

Sau đó drone được hạ cánh bằng:

```text
commander land
```

PX4 báo:

```text
INFO  [commander] Landing detected
INFO  [commander] Disarmed by landing
```

Nghĩa là drone đã hạ cánh và tự động Disarm thành công.

### Kết luận phần Offboard

Bài kiểm thử Offboard đã hoàn thành thành công theo chuỗi:

```text
ROS 2
  ↓
gửi lệnh Offboard
  ↓
PX4 nhận lệnh
  ↓
ARM
  ↓
Takeoff
  ↓
Bay ở chế độ Offboard
  ↓
Landing
  ↓
Disarm
```

Kết quả:

```text
ROS 2 ↔ PX4       : PASS
Offboard Mode     : PASS
ARM               : PASS
Takeoff           : PASS
Landing           : PASS
Disarm            : PASS
Failsafe          : Không kích hoạt
```

## 3. Cấu hình SITL cho bài kiểm thử

Trong bài kiểm thử này không sử dụng Ground Control Station.

PX4 ban đầu báo:

```text
Preflight Fail: No connection to the GCS
```

Để cho phép chạy SITL không cần GCS:

```text
param set NAV_DLL_ACT 0
```

PX4 tiếp tục báo:

```text
Preflight Fail: system power unavailable
```

Do SITL không có phần cứng nguồn như flight controller thật, power supply check được vô hiệu hóa bằng:

```text
param set CBRK_SUPPLY_CHK 894281
```

Kiểm tra:

```text
param show NAV_DLL_ACT
param show CBRK_SUPPLY_CHK
```

Giá trị sử dụng trong bài test:

```text
NAV_DLL_ACT = 0
CBRK_SUPPLY_CHK = 894281
```

> Lưu ý: các cấu hình này chỉ được sử dụng cho môi trường SITL. Không áp dụng mặc định các cấu hình vô hiệu hóa safety check này cho drone thật.

# 6. Hướng dẫn chạy lại SITL và Offboard

Để chạy lại bài kiểm thử, sử dụng 3 terminal Ubuntu 24.04.

---

## 6.1. Terminal 1 - PX4 SITL + Gazebo

Mở Ubuntu 24.04:

```powershell
wsl -d Ubuntu-24.04
```

Khởi chạy PX4 SITL:

```bash
cd ~/PX4-Autopilot
make px4_sitl gz_x500
```

Chờ tới khi xuất hiện:

```text
pxh>
```

Nếu cần thiết, cấu hình lại SITL:

```text
param set NAV_DLL_ACT 0
param set CBRK_SUPPLY_CHK 894281
```

Kiểm tra:

```text
param show NAV_DLL_ACT
param show CBRK_SUPPLY_CHK
```

---

## 6.2. Terminal 2 - Micro XRCE-DDS Agent

Mở terminal Ubuntu 24.04 thứ hai:

```bash
MicroXRCEAgent udp4 -p 8888
```

Giữ terminal này chạy.

Khi PX4 kết nối thành công sẽ xuất hiện thông tin về session, participant, publisher và subscriber.

---

## 6.3. Terminal 3 - Kiểm tra ROS 2

Mở terminal Ubuntu 24.04 thứ ba:

```bash
source /opt/ros/jazzy/setup.bash
```

Kiểm tra topic:

```bash
ros2 topic list
```

Cần có ít nhất:

```text
/fmu/in/offboard_control_mode
/fmu/in/trajectory_setpoint
/fmu/in/vehicle_command
```

Nếu các topic xuất hiện thì kết nối ROS 2 - PX4 đã sẵn sàng.

---

## 6.4. Terminal 3 - Chạy Offboard

Trong cùng Terminal 3:

```bash
source /opt/ros/jazzy/setup.bash
source ~/ws_px4/install/px4_msgs/share/px4_msgs/local_setup.bash

~/ws_px4/build/px4_ros_com/offboard_control
```

Giữ node chạy.

Sau vài giây, tại Terminal 1 có thể xuất hiện:

```text
INFO  [commander] Armed by external command
INFO  [commander] Takeoff detected
```

Kiểm tra:

```text
listener failsafe_flags
```

Cần thấy:

```text
offboard_control_signal_lost: False
```

Tiếp tục:

```text
commander status
```

Kết quả mong đợi:

```text
Armed
navigation mode: Offboard
in failsafe: no
```

---

## 6.5. Hạ cánh

Không nhấn `Ctrl+C` node Offboard khi drone vẫn đang bay.

Tại Terminal 1:

```text
commander land
```

Chờ tới khi xuất hiện:

```text
Landing detected
Disarmed by landing
```

Kiểm tra:

```text
commander status
```

Kết quả:

```text
Disarmed
in failsafe: no
```

Lúc này mới quay sang Terminal 3 và nhấn:

```text
Ctrl+C
```

để dừng node Offboard.

## 8. Kết luận

VT-02 đã hoàn thành yêu cầu.

PX4 SITL + Gazebo chạy thành công với mô hình X500. ROS 2 kết nối được với PX4 qua Micro XRCE-DDS Agent và chương trình Offboard có thể gửi lệnh ARM, thực hiện Takeoff, duy trì chế độ Offboard, Landing và Disarm.

File ULog của lần chạy thành công đã được xác định và lưu SHA256 để phục vụ kiểm chứng.

Kết quả này tạo nền tảng cho các bước tiếp theo của ĐT1, trong đó kết quả từ module phát hiện và theo dõi người sẽ được chuyển thành lệnh điều khiển Offboard gửi tới PX4.
